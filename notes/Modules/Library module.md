# Library module (`library.js`, `GMLib`)

Pure functions shared by the [[Content script]], the [[Settings page]] and the [[Viewer]] (loaded before each; copied into the archive beside `index.html`). No page or extension APIs, so it's the easiest part to unit-test (`npm test` covers the phone backup functions, the importers' records and people). Exposed as `globalThis.GMLib`.

## What a chat says (`analyse`)
The analysis the [[Obsidian notes]] keep in their manifest lives here now (it was `obsidian.js`'s, which calls it through `L()`), so the notes and the viewer's graph ([[Viewer]]) say the same of a chat. `analyse(msgs, periods)` reads a chat's messages once and returns `{ sent, recv, calls, media, kinds, years, hours, week, reply, starts, talks, longest, first, last, days, mdays, terms, yterms, names, emoji, links, files, events, senders, periods }`: counts each way (calls counted apart, system messages skipped), media by kind (`p` photos, `v` videos, `a` voice notes, `f` files) and the saved `files` as `[file, day, me, kind]`, messages per year `[received, sent]` (your messages at index 1), by hour and weekday, reply-time histograms each way (`REPLY` buckets in minutes, `REPLY_TEXT` their words; `usually(h)` the median, from 5 replies), conversations (a new one after six hours' pause, or on a new day when untimed) and who started them, the longest, the first and last, messages per day (`days`) and photos per day (`mdays`; `PHOTO_DAY` or more make a photo day), who said what in a group (`senders`, by number when there is one), capitalised mid-sentence words (`names`, for mentions), emoji each way, the newest links, the events as `[day, kind, me, hint]` (`bday`, `anniv`, `congrats`, `holiday` from `HOLIDAYS`, `trip`, `meet`), and the words and phrases (`termsIn`, over `STOPWORDS`; `terms`: `[uses, first day, last day, the day most, uses that day]`, `yterms` each year's top 12). Days in `terms`, `events` and `files` are day numbers (`dayNum`/`numDay`, `weekday`); `periods` is passed through for the notes. `mergeAnalyses(list)` adds a person's chats up; `standout`, `byYear` and `mentionsOf` (with `AMBIG` and `WORD`) are the topics and mentions [[Obsidian notes]] describes.

It reads both message shapes, decided once per call from the first message (`shapeOf`) and read through one set of accessors, so there's no branching per message: `messages.json` records (`direction`, `timestamp`, `timestamp_precision`, `text`, `sender`, `sender_number`, `kind`, `media[].kind`/`file`), which the notes pass, and the compact `chat.js` messages `compactMessages` writes (`d`, `t`, `p`, `x`, `s`, `m[].k`/`f`), which the viewer passes. `compactMessages` writes a compact message's `kind` and `sn` (sender number) since the Graph view, so a call and a group's senders read the same from both shapes; a `chat.js` written before then has neither, so there a call counts as a received message and a group's senders go by name until the chat is written again. `files` keeps the path each shape has (from the chat's folder in a record, from the library root in a compact message); everything else is the same for the same chat, which `test/people/run.mjs` checks from both shapes.

## Rules for changing it
- Keep it pure: anything that needs `chrome.*`, the DOM or a file handle belongs in the caller. `io` objects (`readText`, `write`) are passed in.
- `norm(m)` accepts both `messages.json` records and compact `chat.js` messages; keep both shapes working when adding fields.
- `summarize()` output is what `data.js` rows look like; Settings and the viewer read those rows, so a new field needs handling in both, with a fallback for libraries written before it existed.
- Changing `checkChat` changes every chat's status the next time it's saved; mention it in the changelog.
