# Sources: one archive for every app

The library is meant to hold **every conversation the owner has, whichever app it was in**: text messages, WhatsApp, Telegram, Discord, Instagram, Messenger, TikTok, Snapchat, and later iMessage and Signal. This note is the model that makes that work; [[Importers]] is the code.

## The model
- **Two levels: source, then account.** A chat's **source** is the app its record came from (`service`); its **account** is which of your numbers or IDs in that app (`account`). Texts are texts in every phone app, so they're told apart by source: Google Messages' texts and iMessage's (with an iPhone's SMS) are different sources, and a second phone or a work number is a second account of one source. A chat only ever joins chats of the same source *and* account (see Accounts below).
- **Every chat belongs to one source.** `messages.json` and its index row carry `service` (`GMLib.SERVICES`: `sms`, `whatsapp`, `telegram`, `discord`, `instagram`, `messenger`, `tiktok`, `snapchat`, `imessage`, `signal`). No `service` means `sms`, shown as **Google Messages**: SMS, MMS and RCS from Google Messages for Web or a phone backup from the Android app. Every library from before services reads unchanged (`GMLib.serviceOf`).
- **One record shape for every app.** A message is the same record a Google Messages backup writes ([[Library format]]): `id`, `direction`, `sender`, `text`, `timestamp` (local minute) with the exact time in `timestamp_raw`, `media[]`, `reply_to`, `reactions`, `edited`. Importers build them with `GMLib.importedRecord`, which adds `sender_id` (the app's own ID for the sender), `sender_name` (what the export called *you*), and `kind` (`system` for notices, `call` for calls). **Your own messages are always `sender: 'Me'`** with `direction: 'sent'`, as in text chats, so the viewer's sides, "You:" and every statistic about you work across apps.
- **Folders by app.** Text chats stay in `conversations/<chat>/` (as always); other apps' go in `conversations/<App>/<chat>/` (`GMLib.chatFolder`), so a WhatsApp chat and the text chat with the same person never share a folder. A text chat named like an app folder gets ` (chat)`.
- **A chat joins only a chat of the same app.** Importing matches by `conversation_id` (`<service>:<the app's chat ID>`, or the chat's name where the export has no ID, as WhatsApp's) or name, among rows of the same service. The live backup (`findEntry` in `content.js`) looks only at text chats.
- **Status "Imported".** A chat from another app's export has `progress.imported = { service, importer, file, at, partial? }` and status `imported` ("Imported", counted as backed up). `partial` says what the export leaves out (Discord: only your messages; Snapchat: only what it still keeps, saved messages and recent ones); the start check is then a warning. A newer export of the same chat adds only what's new: importers give every message a stable `id` (the app's ID, or `GMImport.stableId` of its time, sender, text and repeat number), so nothing is added twice.
- **Media an export doesn't have** is listed with `file: null` and `skipped: '<why>'` (status "Not saved (by choice)"), with `url` when the export only links to it (Discord, some Meta shares).

## Accounts
- **Which of your numbers or IDs.** `account` (an ID: a phone number, an Apple ID, a Telegram account…) and `account_label` (how it shows) on a chat's `messages.json` and index row. **No `account` means the source's main account**, so every chat from before accounts is in its main account.
- **Folders:** a second account's chats go in `conversations/<App> - <account>/<chat>/` (`GMLib.chatFolder`), e.g. `conversations/Google Messages - (555) 019-9999/`.
- **IDs compare loosely** (`GMLib.accountKey`): numbers by their last ten digits, anything else by its lower case.
- **`accounts.json`** (library root): `{ version: 1, main: { <service>: { id, label } } }`, which ID each source's main account is, once an import has said.
- **Where the ID comes from:** a phone backup's manifest `owner.number` (the Android app writes it when the phone knows its own number); an importer's `owner` (Telegram's phone number or user ID, Discord's username, TikTok's and Snapchat's usernames, Meta's profile name; WhatsApp's export doesn't say). Google Messages for Web is always the main account (it reads the paired phone).
- **Deciding** (`resolveAccounts` in Settings, before the confirm): no ID → main account. An ID that's the main one's → main. A different ID → a separate account. The source's first ID, with none of its chats here yet → becomes the main. The first ID when chats of that source are already here but no main ID is known → Settings asks "Are they from this same number?" (`askSameAccount`): yes makes it the main; no keeps these apart.
- **Shown** as "Google Messages · (555) 019-9999" (badges, filters, Home, About); the main account's chats get a badge too once their source has a second account.

## What's Google Messages only
Backing up from Google Messages for Web, "Back up everything" and its coverage check (`verificationOf` compares Google's list with **the main Google Messages account's chats**), photo fetching and upgrading, and the backup list: Settings offers them only on those rows (`isLive`). The Phone restore files take one Google Messages account at a time ("Texts from", once there's more than one; `isText`, `restoreRows`); other apps' chats never go back on a phone as texts.

## People: one person, many apps, accounts and numbers
A **person** is a set of one-to-one chats (`GMLib.people`, [[Library module]]). Group chats, app channels and Telegram's "Saved Messages" aren't anyone (`isPersonChat`); a person's groups are found separately.
- **Joined by themselves** when chats share an **identifier** (`GMLib.personIds`): a phone number (last ten digits, from the contact card's `num` or a chat named by its number, in any app: texts, WhatsApp, iMessage), an email address, or a **handle in one app** (`<service>:<handle>`: a Telegram user ID, a Discord ID, a TikTok or Snapchat username), so the same Telegram user in two of your accounts is one person. Importers put handles in the contact card (`handle`), and the index row keeps them (`contact.people[].h`).
- **Suggested, never joined by themselves,** when only a **name** matches (`GMLib.nameKey`: no case, accents or punctuation). Names are what you or they typed: an Instagram display name and a contact's name can be two people. Two to four people with one name make suggestions (`suggestions`: pairs); more (forty "Mom"s) don't.
- **The owner decides** in the viewer's People tab ([[Viewer]]): *Same person* (`joinPeople`), *Not the same* (`keepApart`: the suggestion goes), *Not them* on one chat (`splitChat`: the chat stands alone, and the person's other chats stay together), *Rename* (`renamePerson`). Saved in **`people.json`** (and `people.js` for `index.html` from disk, [[Library format]]) by **chat** (`GMLib.chatKey`: the conversation ID, else the folder), not by person, so new chats and re-imports don't disturb it: `{ version: 1, joined: [[a, b]], apart: [[a, b]], alone: [a], names: { a: name } }`.
- **A person's name:** the one the owner gave; else from a chat whose names are the owner's own contacts (texts, WhatsApp, Signal, iMessage), else the busiest chat's; else their number.
- **The address book** (`book` = `contacts.json`, from a phone backup with *Save all my contacts* on; `contactIndex`): a chat is tied to the contact with one of its numbers or email addresses, or, in an app whose names come from the phone's contacts (`BOOK`: texts, WhatsApp, Signal, iMessage), with its name, when only one contact has that name. A number, email or name on two contacts ties to neither. A tied chat gets `contact:<key>` and the contact's numbers and emails as ids, so a person's texts, their WhatsApp chat (named but numberless in the export) and a Telegram chat from their other number become one person, named as in the address book (after a name the owner gave), with `contact` set. Group members known only by name are tied the same way, for `groupsOf`.
- **The phone's contact** (`card` on a person in a chat's card, from a phone backup): its other numbers and emails, and the contact itself (`contact:<lookup key>`), are ids too, so chats with each of someone's numbers join up by themselves.
- **Groups** (`groupsOf`): group chats with one of their identifiers in the contact card, or their name in a group *of the same app* for a member the group knows only by name (a member with a number is that number's person, not everyone with their name).
- **Shown** in the viewer's People tab (everyone, a person's chats, groups and one timeline across them), in each one-to-one chat's header ("👤 Sam · also in WhatsApp · maybe Instagram?"), on About, and as the People notes of [[Obsidian notes]].

## Kept apart: codes, promotions and automated texts
What clutters an archive is told apart **per chat** ([[Library module]]: `chatTraits`, `senderOf`, `chatKind`), never per message:
- **Who it's with** (`senderOf`): a `group`; a `contact` (a name of yours); a `short` code (3 to 6 digits); a `business` sender ID (letters, as "AMAZON" or "VM-BANKX", in the contact card's number, or a capitals-only name with no number, texts only); or a `number` with no name saved.
- **What came in** (`chatTraits`, counted over messages from the other side): **codes** (4–8 digits, or `G-123456`, `123-456`, with words that say so: code, OTP, one-time, passcode, PIN, 2FA, verification, sign in, log in, "don't share", and a few other languages' words for code, in a text of 400 characters or fewer); **promotions** (the lines marketing texts must carry, in their many spellings and any capitals: "Reply STOP", "Rply STOP", "Text back STOP", "Txt STOP to end", "STOP=end", "STOP2END", "STOP to quit", "STOP-end", "End=STOP", "opt out", "unsubscribe", "Reply HELP", "HELP4help", "Msg&data rates may apply", "Msg freq", "4 msgs/mo"; "Reply END", "Text QUIT" and the like count only in capitals, so "I'll text end of day" doesn't); **links**; and **links with scam-like or sales words** (prize, claim, package, unpaid, refund, crypto, sale, % off, shop now, promo code, hiring, donate…). And how many you sent. The index keeps them per chat (`traits` in `data.js`, with `v`, the rules' version, `TRAITS_VERSION`: where a row's traits are used to leave chats out, a row counted by older rules is counted again from its chat).
- **The kinds** (`chatKind`): `codes` when half or more of what came in are codes; `promos` (promotions and spam) when a fifth or more are promotions, or a number with no name sent mostly links with scam-like words (20 messages or fewer); `automated` for any other short code or sender ID. A **contact** needs more (four in five codes and at least two; half promotions; never "automated") and **any reply** to a contact makes it a conversation. **Three or more messages of yours** make any chat a conversation; groups never count. A chat the owner kept ("It's not": `labels.json` `keep`) or labelled with anything but Spam is never one; one labelled Spam counts as promotions and spam for leaving out (`chatKindFor`).
- **The viewer** keeps them out of All chats, People, Search, Media and Analysis, in folders of their own, unless **Show them everywhere** ([[Viewer]]).
- **The Android app** has the same three switches for phone backups (Settings → *Leave out of phone backups*; `Clutter.kt`, the same rules in Kotlin, checked against the same cases: `test/filters/cases.json`). On the phone a chat is judged by its address and the contact's name, a starred contact is never one, and a backup that had such a chat drops it ([[Android app]]).
- **Leave out of your archive** (Settings; `skipCodes`, `skipPromos`, `skipAutomated`, all off at first): "Back up everything" skips them and imports leave them out ([[Backup run]], [[Settings page]]), and **Find the ones already in my archive…** moves those already there into `removed-chats/` and onto `excluded` with the reason. Backing up one chat yourself, and the backup list, are never filtered: those are chats you chose.

## Who "me" is
An export doesn't always say whose it is. In order: the export's own account (Telegram's `personal_information`, Discord's `account/user.json`, TikTok's profile, Snapchat's `account.json`, Meta's profile files); the export marking your messages (Snapchat's `IsSender`, older downloads' "Sent" list); a one-to-one chat named for the other person (WhatsApp: the other name is you, and no one is when only they wrote); the one name in every chat (Meta); else Settings asks "Which one is you?" and remembers the answer per app (`chrome.storage.local` `myNames`, see [[Storage and settings]]).

## Modules: one file per app
Google Messages is the core; every other app is a **module** that augments it: one file in `extension/modules/` (`GMLib.addModule`, [[Importers]]) with the app's name, colour, folder, what identifies a person there, how to get its export, what the Android app does with it, and the reader of its export. `GMLib.SERVICES` is filled from the modules, so folders, labels, colours and People all follow them, and Settings' **Apps** tab shows a card per module: Google Messages first, then each app with what the archive has from it and how to bring more in, then those that can't come in yet (iMessage, Signal) and why.

**On the phone**, the Android app has a section per app beside Google Messages's (`Apps.kt`): an export shared to it (WhatsApp's "Export chat") or a download shared or added there (Meta's, Snapchat's, TikTok's, Discord's) goes into the next phone backup (`Exports.kt`; [[Restore package]] → Exports), and comes into the archive with that backup, read by the same modules ([[Android app]]).

## Adding an app
Write `extension/modules/<app>.js`, add it to `options.html`, `viewer.html` and the manifest's content script (`npm run check` says where if one is missing), and add a made-up export to `test/importers/run.mjs` ([[Importers]] → Adding an app). If a phone can export it, add it to the Android app's `Apps.kt` too. Nothing else changes: merging, the index, checksums, the viewer and the Apps tab are already source-neutral.

## What each app's export holds
- **WhatsApp**: one chat per export, as text (and its media, if asked for), capped by WhatsApp; no chat IDs, no account. A folder of several exports (text files or their zips) comes in at once.
- **Messenger**: Meta's "Download your information" has the chats from before end-to-end encryption (most chats became encrypted in 2024). The encrypted ones are in **Messenger's own download** (secure storage), a zip of one JSON per chat with no chat IDs: bring in both. HTML downloads can't be read; Settings says to ask for JSON.
- **Snapchat**: "My Data" has only what Snapchat still keeps (saved messages and recent ones), with photos and videos when Chat Media was ticked. Snaps themselves are only listed (`snap_history.json`: who and when, no content) and aren't brought in. A big download comes in parts (the chats in one, photos in others): unzip them into one folder. **The gap is filled from Snapchat for Web**: with it turned on (Settings → Apps), the chats the owner opens there are kept as they're read, unsaved messages included, and put in the archive on **Put them in my archive** ([[Snapchat Web page]], [[Importers]] → Web page readers). They join the download's chats by name, and their messages match the download's by side and words within the time their group was sent, so the two together add nothing twice. Snaps are never read.
- A download in parts, or in HTML: importers say so (`explain`, [[Importers]]) instead of "isn't an export this can read".

## Not yet
The sources a browser can't reach (iMessage, Signal Desktop, iPhone backups) are planned for a small native helper beside an app on Chrome or Edge: see [[Desktop app]].
- **WhatsApp beyond one chat at a time**: WhatsApp has no whole-account export with messages ("Request account info" has none). The phone's own copies are out of reach: Android's `msgstore.db.crypt15` needs the backup's key, and an iPhone's `ChatStorage.sqlite` is inside a Finder backup, reachable the way iPhone texts would be (an unencrypted backup, through the helper). WhatsApp for Mac keeps SQLite databases in its group container (`~/Library/Group Containers/group.net.whatsapp.WhatsApp.shared/`): a candidate for the helper, once which file holds the messages on a Mac has been checked on a real one (reports disagree).
- **iMessage**: the Messages database on a Mac (`~/Library/Messages/chat.db`, readable only with Full Disk Access) is SQLite, with newer messages' text inside an `attributedBody` blob and recent ones still in `chat.db-wal`. The helper reads a copy of it, with the attachments folder; see [[Desktop app]] and [[Known issues]].
- **Signal**: no plain export exists (its backups are encrypted with a passphrase).
- **iPhone texts** (SMS/iMessage from an iPhone backup) would be the same chat.db, inside an iTunes/Finder backup.
