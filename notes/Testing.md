# Testing

There are no automated tests beyond `npm run check`. Changes are tested on a mock Google Messages page, then in Chrome with the real extension.

## Always
```bash
npm run check
```
Manifest, versions, referenced files, no inline scripts, `node --check` on every script. CI runs the same on every push and PR (`.github/workflows/ci.yml`).

## The mock page (how 0.4.x was tested)
The harness was built in a session scratchpad and **is not in the repo** (see [[Known issues]]: worth adding as `test/mock/`). To rebuild it:

- **Server**: a tiny Python `http.server` on `127.0.0.1:8765` that sends `Cache-Control: no-store`, plus a `POST /save?path=…` that copies a file out of the page's private storage to disk for inspection.
- **Mock Messages page** (`/web/conversations/123/`): fake custom elements matching [[Google Messages page]] (`mws-message-wrapper msg-id is-outgoing`, `mws-tombstone-message-wrapper`, image parts with canvas-generated JPEGs: a 160×120 thumbnail in the chat, 640×480 in the "viewer"), a spinner and batches of older messages that load as you scroll to the top, a conversation list item and a header link. Query flags: `slow=1` (slow batches), `lazy=1` (lazy images).
- **chrome stub**: `window.chrome` with `runtime.onMessage.addListener` saving the listener as `window.__listener`, `sendMessage` recording into `window.__sent`, and `storage.local` backed by `localStorage`. Runs are started by calling `window.__listener({ type: 'gm-media', … }, {}, reply)` from the console.
- **Backup folder**: the Origin Private File System. Put `navigator.storage.getDirectory()` → `lib` into IndexedDB `gm-exporter`/`kv`/`backupDir`; the real `writer.html`/`writer.js` then work unchanged (same origin).
- **Settings, popup, viewer**: served as-is with a `stub.js` loaded first (fake settings, schedules, runs; `gm-to-tab` returns a canned chat list). The viewer runs with `?library=1` against the same OPFS folder.
- **Cache busting**: add `?v=N` to every script tag and bump N on each change; the browser otherwise keeps old copies.
- **Checks to run** (a `__check()` helper in the console): the chat's `progress.json` status, `media-index.json` counts, files on disk vs files in use (no orphans), journal folder gone, `SHA256SUMS.txt` matching ("Check no files have changed" in Settings, or `shasum -a 256 -c` on a copy saved with `/save`).

Limits: lazy images only load while the browser pane is **visible**; a hidden pane makes photos fail (a harness limit, not a bug). Upgraded file names end in ` (2)`.

## The background worker in Node
`background.js` has no DOM, so its message handlers can be run in Node: define a stub `globalThis.chrome` (in-memory `storage.local`, `runtime.onMessage.addListener` capturing the listener, no-op `alarms`, `action`, `notifications`, `downloads.onDeterminingFilename`), evaluate the file with `new Function(source)()`, then call the listener with a message. Used to check `gm-backup-status` with and without `statusOnly`.

## A multi-year library (0.5.0.0)
`test/perf/genbig.mjs` writes a synthetic library (one chat of 100,000 messages over 4 years with ~2,900 photos, plus 299 smaller chats; 408,000 messages; all names and numbers made up) using `library.js`, with a `files.json` list. Serve it from the mock server, copy it into OPFS (fetch each file, 12 at a time, about 30 s), point IndexedDB `backupDir` at it, and open the viewer (`?library=1`) and Settings. `test/perf/bench.mjs` times the per-pass and per-save costs of a backup on a 100,000-message chat, 0.4.x against 0.5.0.0. Compare against the previous viewer by serving `git show main:extension/viewer.js` as `viewer-old.js`.

A second made-up library (three people, a group) checks a person's note: the gist, who starts, moments linked to their day (in the chat note, and in a month note), the years table, when you talk, a shared topic as a note and one person's word as plain text, who's named and who names them, groups in common, the photos and links notes, People's most recent and lost touch, a one-way sender (tagged, out of topics and the lists, in People's One-way), what a phone contact adds (photo, starred, nickname, work, birthday and the birthdays moment, a label note, relations linked), a phone contact with two numbers joining into one person, and `phoneChat`/`contactSummary` carrying the contact, the address book tying texts, a numberless WhatsApp chat (by name) and a Telegram chat (another number) into one person while an Instagram name or a name two contacts share doesn't, a group member tied by name, and a person note from the address book, and, in a third, the days, events, photos and phrases: events found in what each side said (a birthday wish and who said it, congratulations and what for, travel and the place, meeting up, Christmas, a group's wish by name), a phrase shared by two people as a topic without its longer variants, a topic note's table, a month note's days linking to them in each chat and its same-day wishes on one line (and no one-way sender), a year note, the calendar, your birthday and a birthday calendar (including one from a group's wish), milestones, travel and meeting up, the photo notes and the calendar's link to them, a person's timeline, a group's gist, the home note, that your writing in a month note stays and a second run writes only the manifest, and what counts as yours for *Delete the notes*, and that a second run with nothing new writes only the manifest.

To see the People tab and the Obsidian card in a browser, make a made-up multi-app library with the `GMLib` functions (as `test/screenshots/demo-library.mjs` does): serve it with `index.html` for the read-only view; for library mode, copy it into the page's origin-private file system (`navigator.storage.getDirectory()`) and store that directory as `backupDir` in IndexedDB `gm-exporter` / `kv`, then open `viewer.html?library=1#people` and `options.html` (Tools) with a stand-in for the `chrome.*` APIs. Answer `prompt` and `confirm` from the console (`window.prompt = () => '…'`) so dialogs don't stop the browser.
`npm test` also runs `test/importers/run.mjs`: a small made-up export for each app (WhatsApp from an iPhone and from Android, Telegram, Discord with a CSV channel, Instagram with Meta's garbled accents, Messenger's encrypted chats' download, TikTok, Snapchat in its current and older shapes), checking each is recognised, you are "Me", dates and media are right, the same export twice adds nothing, and the chats get their app, folder and "Imported" status. For WhatsApp also: an iPhone's marked notices (a group's and a one-to-one chat's), Android's one-to-one chat with its senderless notice (not a group, you found without asking), attachments and left-out media in other languages, six languages' dates and times, a folder of text files and a folder of zips (`GMImport.openAll`, with real zips from `GMZip.ZipWriter` and a stand-in directory handle). And what an HTML download or a part with only photos says (Facebook, Snapchat); a made-up Snapchat for Web capture (`GMImport.webSource`: you and them, a reply, a photo and a sticker noted, each message's span, nothing added twice) and its matching with the same chat from Snapchat's download both ways, by side and words within a group's span (`GMLib.unknownIn`); a made-up phone backup (`GMLib.tarHeader`) carrying two WhatsApp exports shared to the Android app, one a .zip and one a chat's .txt and its photo, plus a file that isn't one (`GMImport.packageExports`); and the modules themselves (Google Messages first and core, every app present with its steps or why not yet, one reader for Instagram and Messenger, their looks in `GMLib.SERVICES`, a text chat named like an app's folder kept apart). The tests load `import.js` and every file in `extension/modules/`, as the pages do (`test/people/run.mjs` loads the modules too, for the apps' names in People and the notes). `npm run check` also fails if a module isn't loaded by `options.html`, `viewer.html` and the manifest's content script. On Android, `AppsTest` checks which app a shared export is from and that the phone's app list matches the modules. The whole import (`GMImport.open` → `mergeExports`) and the viewer's app filter and links were checked in a browser the same way as below, with the private storage (OPFS) as the library.

`npm test` runs `test/restore/import-phone.mjs`: a made-up phone backup and library with the awkward cases (numbers written differently, a business and a short code, a photo and its caption split, a minute off, two identical texts, importing twice), checking chat matching and which messages are new. CI runs it.

The whole import (`phoneSource` → `mergeExports` → `importChat`) was checked in a browser by serving `options.html` from a scratch folder with a stand-in for `chrome.*` (storage in memory, `getURL` relative) and the origin-private file system (`navigator.storage.getDirectory()`) as the backup folder: a zip export first, then the emulator's phone backup, then the same again (nothing added), then `viewer.html?library` with that folder put in IndexedDB under `backupDir`.

## The Android app on an emulator
One-time: JDK 17 (`brew install openjdk@17`), Android command-line tools, then `sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0" "emulator" "system-images;android-35;google_apis;arm64-v8a" "cmdline-tools;latest"` and `avdmanager create avd -n gmtest -k "system-images;android-35;google_apis;arm64-v8a" -d pixel_7`. Use a **google_apis** image (not google_play): it allows `adb root`, which is how the SMS database is read back.

1. `emulator -avd gmtest -no-window -no-audio -no-boot-anim -no-snapshot`, wait for `sys.boot_completed`, `adb root`.
2. Build and `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`.
3. Make a package with the extension (Settings → Phone restore) from a test library (`test/restore/gensmall.mjs`: a one-to-one chat with same-minute bursts and photos, a group, a short code, one chat without a number), push it to `/data/local/tmp`, and `adb shell run-as io.github.trikhster.messagearchivist cp /data/local/tmp/test.tar files/test.tar` (a file pushed as root elsewhere isn't readable by the app).
4. `adb shell cmd role add-role-holder android.app.role.SMS io.github.trikhster.messagearchivist 0`, then `adb shell am start -S -n io.github.trikhster.messagearchivist/.MainActivity --es restore_path /data/data/io.github.trikhster.messagearchivist/files/test.tar --ez auto true`. The log line `MessageArchivist: restored sms=… mms=… skipped=… failed=…` says how it went.
5. Read back: `adb shell "content query --uri content://sms --projection date:type:address:body --sort 'date ASC'"`, `content://mms`, `content://mms/<id>/addr`, `content://mms/part`. Run it again: everything should be skipped.
6. `cmd role add-role-holder android.app.role.SMS com.google.android.apps.messaging 0`, `pm clear com.google.android.apps.messaging`, open Messages ("Use Messages without an account") and check the chats look right, especially groups.
7. Backup: `adb shell pm grant io.github.trikhster.messagearchivist android.permission.READ_SMS`, then `am start -S -n io.github.trikhster.messagearchivist/.MainActivity --es backup_path /data/data/io.github.trikhster.messagearchivist/files/backup.tar`; the log says `backed up chats=… sms=… mms=… media=…`. Pull it (as root) and `node test/restore/compare.mjs <the package you restored> backup.tar`: every chat should be identical. A made-up contact for names: insert a raw contact and its name and phone rows with `content insert --uri content://com.android.contacts/...`.
8. Updates: back up with `--ez media false`, `run-as … cp` the file, then `--es backup_path <copy> --ez update true` (photos on): 0 messages and every photo added, and `compare.mjs` against a backup made with photos shows them identical. Add texts as root (`content insert --uri content://sms --bind address:s:… --bind body:s:… --bind date:l:… --bind type:i:1 --bind thread_id:l:…`), update again: only those are added, as `threads/<n>.2.ndjson`, version 2. A restore of that file into the same phone skips everything (it read every piece). Daily: turn it on from the done screen, then `adb shell cmd jobscheduler run -f io.github.trikhster.messagearchivist 7`; the log says `daily backup added=…` and the first screen shows it.
9. Contacts and addresses: star a test contact (`content update --uri content://com.android.contacts/contacts --bind starred:i:1 --where _id=1`); a text to two numbers at once (`content insert --uri content://sms --bind address:s:'5550300001;5550300002' …`) makes one canonical address holding both. A backup then has that chat with two addresses, and the starred contact's `people[].starred`.
10. The screens: without `auto`, the file opens on the review screen; tap Restore to go through the permission and role dialogs. `adb shell am startservice -a io.github.trikhster.messagearchivist.STOP -n io.github.trikhster.messagearchivist/.RestoreService` stops a restore. Switching the role back (step 6) ends the app's process: reopen it, it should show the result again. `adb shell cmd uimode night yes` / `no` for dark mode. Screenshots: `adb exec-out screencap -p > shot.png`. For the README's (`docs/screenshots/android/`, made-up data only): demo mode for a clean status bar (`adb shell settings put global sysui_demo_allowed 1`, then `am broadcast -a com.android.systemui.demo -e command enter`, `-e command clock -e hhmm 1200`, `-e command network -e wifi show -e level 4 -e fully true`, `-e command network -e mobile hide`, `-e command battery -e level 100 -e plugged false`, `-e command notifications -e visible false`; `-e command exit` afterwards), then `sips -s format jpeg -s formatOptions 82 -Z 1200 shot.png --out name.jpg`. The README's other screenshots (`docs/screenshots/viewer-*.jpg`, `setup.jpg`) come from a made-up library: `node test/screenshots/demo-library.mjs extension/library.js <folder>` (a family group with photos, one-to-one texts, and WhatsApp and Telegram chats with the same people, more messages lately). Build the app (`npm run app`), copy the folder into `dist/site/demo`, serve it (`npm run serve-app`), and in a 1180×746 dark window at 2× put it in the private file system as `backupDir` (as above); then the app's Chats, People (a person with chats in two apps open) and Analysis. The setup page's (`setup.jpg`) is Home before a folder is chosen, with the `app` class taken off `<html>` so it shows the extension's steps (that class only hides `.ext-only` and shows `.app-only`). The browser pane can't save full-size pictures; headless Chrome over its debugging port (`Page.captureScreenshot`) can. Then `sips -s format jpeg -s formatOptions 82 -Z 1600`. With a phone plugged in as well, `export ANDROID_SERIAL=emulator-5554` so nothing goes to the phone.

## Leaving out codes on the phone (Android)
`./gradlew testDebugUnitTest` checks `Clutter` on the shared cases. On the emulator (as root): add made-up texts with `content insert --uri content://sms/inbox --bind address:s:72727 --bind 'body:s:Your Acme code is 123456. Do not share it.' --bind date:l:<ms> --bind read:i:1` (a short code with codes; `SHOPCO` with "Reply STOP to opt out"; a number with "Claim your prize at example-prize.xyz/claim"; `88888` with alerts; and a number you've answered three times via `content://sms/sent`); back up with the `backup_path` hook; turn switches on in Settings (or check `run-as … cat shared_prefs/leave_out.xml`); back up again, and update a copy of the first file with `--ez update true`. Read each package's `manifest.json` (`threads`, `left_out`): the conversation and anything not ticked stay, the rest go, from the update too. The log line ends `leftOut=N`. Delete `shared_prefs/leave_out.xml` afterwards.

## Choosing chats on the phone (Android)
On the emulator, with the `backup_path` hook: back up every chat into one file and read its `threads` for the keys (each chat's `addresses`, sorted, joined with commas). Then `--esa only '<key>,<key>'` into a new file (a group's key with its commas written `\,`): just those chats, `history[-1].chosen`, and the log line ends `chosen=N`. Copy the full file, add a text to a chosen chat and to another (`content insert`, the body quoted for the device shell), and update the copy with `--ez update true --esa only '<the chosen key>'`: only that chat grows and every chat is still there; update again without `only` and the other grows. With `shared_prefs/leave_out.xml` on, a chosen code chat still goes in. The screens: with `shared_prefs/leave_out.xml` on, **Back up to another file** → **Chats**: the Codes, Promotions & spam and Automated chips start off, with "N chats hidden"; sort by Largest (each row shows a size; to check one by hand, as root, add up the chat's text lengths and its photos' file sizes in `/data/user_de/0/com.android.providers.telephony/app_parts/`); turn Codes on and Groups off; **Done**; **Save backup** to Downloads under a test name: the file has the code chat and no group, and the done screen says how many were chosen, with no automatic switch. `GMLib.readPackage` reads the file. `./gradlew testDebugUnitTest` runs `ChatChoiceTest`.

## The app
`npm test` runs `test/app/run.mjs` on the build ([[App]] → Tests). In a browser:
- `npm run serve-app` builds it and serves `dist/site` at `http://localhost:8080/app/` (`scripts/serve-app.mjs`; only this computer can reach it). `localhost` is a secure address, so installing, the offline copy and folder access all work: install it from Chrome's address bar and use it as the real app. (`python3 -m http.server` can't be started from the desktop app's preview runner: macOS refuses it the working folder.)
- **The backup folder**: as for People, copy a made-up library into the page's origin-private file system and store that directory as `backupDir` in IndexedDB `gm-exporter` / `kv`; the app's Home, Backups, Tools and viewer then use it. Put a made-up phone backup there too and pass its handle to `importAnything(false, [handle])` to check what opening a `.tar` with the app does (`window.confirm = () => true` first).
- **Offline**: stop the server and reload `/app/` and `/app/viewer.html?library=1`: both come from the offline copy.
- **A new version**: change a served file (append a comment to `sw.js`), reload: the notice appears; **Restart now** switches.
- **Installable**: the browser pane doesn't offer installing, so ask a throwaway headless Chrome over the DevTools pipe: `Page.getInstallabilityErrors` (empty when installable) and `Page.getAppManifest` (what Chrome read; its report leaves out some fields, file handlers among them).
- Windows opened by a script (not a click) are blocked as pop-ups: navigate to `viewer.html?library=1` instead.

## Scenarios worth repeating
- First backup of a chat; carry on after **Stop…**; a simulated crash mid-run (reload the page), then back up again: journal recovered, no lost messages.
- Speed run → status `messages` → **Fetch photos** goes back only to the oldest target.
- **Retry failed** with a deliberately broken image.
- **Upgrade to full size**: thumbnails replaced, old files removed, checksums still match.
- Settings → **Check every photo** after altering one file and deleting another; **Fetch the missing ones again** brings it back at full size.
- Viewer: flags saved to `labels.json`, Review tab edits, `#labels/<id>`.

## In Chrome
Load `extension/` unpacked, reload the extension **and** the Messages tab after each change. Try it on a short real chat. Check the run log (Settings → Past runs) for DEBUG lines. Never commit or share anything from a real backup.
